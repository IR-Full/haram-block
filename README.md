# Block Haram

Расширение для Chromium-браузеров (Chrome, Edge, Brave, Opera, Яндекс), которое блокирует сайты для взрослых.
Работает локально, без телеметрии и без кнопки отключения.

## Как это работает

```
Запрос ──► declarativeNetRequest (движок браузера, без JS)
              ├─ документ / iframe  → redirect на blocked.html
              └─ картинки, видео, скрипты с адалт-CDN → block
```

- **~535 000 доменов** из четырёх проверенных источников ([THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)).
- Правило DNR с `requestDomains` вмещает тысячи доменов вместе с поддоменами: весь список занимает ~214 правил.
  Проверку выполняет сам браузер в сетевом стеке, поэтому service worker не просыпается и на каждый запрос не тратится ни одной миллисекунды JS.
- Страница блокировки показывает аят 24:30 и считает попытки (счётчик хранится только в `chrome.storage.local`).

### Безопасный поиск

Второй набор правил (`public/rules/safesearch.json`, генерируется из [`tools/build-lists/safesearch.ts`](tools/build-lists/safesearch.ts)) принудительно включает строгий режим:

| Поисковик     | Как                                                    |
| ------------- | ------------------------------------------------------ |
| Google        | `safe=active` на всех доменах Google                   |
| Bing          | `adlt=strict`                                          |
| DuckDuckGo    | `kp=1`                                                 |
| Yandex, ya.ru | `family=yes`                                           |
| Brave Search  | `safesearch=strict`                                    |
| Yahoo         | `vm=r`                                                 |
| Startpage     | `qadf=heavy`                                           |
| YouTube       | заголовок `YouTube-Restrict: Strict` (Restricted Mode) |

Параметр добавляется внутренним редиректом Chrome ещё до отправки запроса, только на страницах результатов поиска.
Явный `safe=off` перезаписывается. Если параметр уже стоит, правило не срабатывает, так что редиректа по кругу нет (это проверяют e2e-тесты).
Что именно фильтрует сам поисковик по этим параметрам, стоит периодически проверять вручную, особенно в Yandex, Yahoo и Startpage.

### Эвристика страницы и самообучение

Для новых сайтов, которых ещё нет в списках, работает [content script](src/entrypoints/content.ts) (~6,5 КБ).
Он срабатывает один раз — когда разобран `<head>`, ещё до отрисовки страницы — и читает заголовок, `description`, `keywords` и `<meta name="rating">`.

- Метка **RTA** или `rating=adult` (адалт-сайты ставят их сами): страница скрывается, домен блокируется.
- Иначе [классификатор](src/shared/classifier.ts) суммирует веса терминов из [словаря](src/shared/adult-terms.ts) на 8 языках. Каждый термин считается один раз, поэтому новость, где слово повторяется, не наберёт порог, а набитый ключевыми словами заголовок адалт-сайта наберёт быстро.
  - счёт ≥ 6 — скрывается только эта страница;
  - счёт ≥ 10 — домен запоминается и дальше блокируется на уровне сети, до отправки запроса.
- Запомненные домены хранятся в двух динамических правилах DNR и **истекают через 30 дней**: если сайт всё ещё адалт, он запомнится снова, а редкое ложное срабатывание исправится само.
- Домены из `allowlist.txt` и поисковики никогда не запоминаются: на них скрывается только конкретная страница.

## Установка (без Chrome Web Store)

```bash
npm ci
npm run build
```

Дальше откройте `chrome://extensions`, включите «Режим разработчика», нажмите «Загрузить распакованное расширение» и выберите `.output/chrome-mv3`.
Затем в «Сведениях» расширения включите «Разрешить использование в режиме инкогнито».

## Разработка

| Команда                 | Что делает                                                            |
| ----------------------- | --------------------------------------------------------------------- |
| `npm run dev`           | Chrome с расширением и HMR                                            |
| `npm run build`         | Сборка списков и расширения в `.output/chrome-mv3`                    |
| `npm run zip`           | Архив для Chrome Web Store                                            |
| `npm run lists`         | Пересобрать правила (скачивания кэшируются на 12 ч)                   |
| `npm run lists:refresh` | То же, но с принудительной перезагрузкой источников                   |
| `npm run lists:report`  | Какие сайты из топ-20k Tranco блокируются (поиск ложных срабатываний) |
| `npm run check`         | typecheck + lint + format + юнит-тесты                                |
| `npm run test:e2e`      | Playwright: настоящий Chromium с расширением, весь трафик локальный   |
| `npm run store:assets`  | Скриншоты и промо-картинки для Chrome Web Store в `store-assets/`     |

### Сборщик списков — `tools/build-lists/`

1. Скачивает источники (`sources.ts`); если скачанный список меньше `minEntries`, источник сломан и сборка падает.
2. Нормализует записи (`normalize.ts`): punycode, отбрасывает IP-адреса, неизвестные TLD и публичные суффиксы вроде `blogspot.com` или `github.io`.
3. Вычитает `allowlist.txt`, где перечислены мейнстрим-платформы и проверенные ложные срабатывания. Поддомены из allowlist остаются заблокированными.
4. Схлопывает поддомены, если в списке уже есть родительский домен.
5. Проверяет, что все домены из `must-block.txt` покрыты.
6. Пишет `public/rules/adult.json` и `public/rules/meta.json` (оба генерируются и в git не хранятся).

Нашли ложное срабатывание? Добавьте домен в `allowlist.txt` с комментарием и выполните `npm run lists`.

## Публикация в Chrome Web Store

Регистрация разработчика — **разовый взнос $5**, дальше публикация бесплатная.
Именно публикация в CWS позволяет в Windows закрепить расширение политикой `ExtensionInstallForcelist`, чтобы его нельзя было удалить или выключить.
Для расширений не из стора эта политика работает только на компьютерах в домене.

### Первый выпуск (вручную, один раз)

1. **Репозиторий.** Создайте публичный репозиторий на GitHub и запушьте проект — ссылка на [`PRIVACY.md`](PRIVACY.md) в нём станет адресом политики конфиденциальности.
2. **Аккаунт разработчика.** Зарегистрируйтесь в [Chrome Web Store Developer Dashboard](https://chrome.google.com/webstore/devconsole) и оплатите $5.
3. **Пакет и графика.**
   ```bash
   npm run zip
   npm run store:assets
   ```
   Архив — `.output/block-haram-<версия>-chrome.zip`, скриншоты и промо-картинки — `store-assets/`.
4. **Карточка.** В панели нажмите «New item», загрузите архив и заполните вкладки текстами из [`docs/store/listing.md`](docs/store/listing.md): описание, категория, обоснование разрешений, политика конфиденциальности.
5. **Отправьте на проверку.** Первая проверка расширения с доступом ко всем сайтам может занять от нескольких дней до пары недель.
6. **ID расширения** появится в панели сразу после загрузки — он нужен для CI и для `install-policies.ps1`.

### Дальнейшие выпуски (автоматически)

[`.github/workflows/release.yml`](.github/workflows/release.yml) собирает, тестирует и отправляет новую версию в стор:

- **Выпуск кода** — поднимите версию и запушьте тег:
  ```bash
  npm version patch
  git push --follow-tags
  ```
- **Обновление списков** — каждый вторник CI сам собирает последний выпущенный код со свежими списками
  (версия `x.y.z.N`, где N — номер дня; правки `allowlist.txt` из `main` подхватываются). Такие обновления проходят обычную проверку, обычно 1–3 дня;
  новые сайты в это время ловит эвристика страницы.

Для отправки нужен доступ CI к Chrome Web Store API v2 через сервисный аккаунт ([документация](https://developer.chrome.com/docs/webstore/service-accounts)):

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект и включите «Chrome Web Store API».
2. Создайте сервисный аккаунт (роли не нужны) и JSON-ключ к нему.
3. В Developer Dashboard в разделе **Account** добавьте email сервисного аккаунта.
4. В репозитории GitHub → Settings → Secrets and variables → Actions добавьте секреты:

| Секрет                                | Значение                                                      |
| ------------------------------------- | ------------------------------------------------------------- |
| `CHROME_EXTENSION_ID`                 | ID расширения                                                 |
| `CHROME_PUBLISHER_ID`                 | ID издателя из **Publisher → Settings** в Developer Dashboard |
| `CHROME_SERVICE_ACCOUNT_CLIENT_EMAIL` | `client_email` из JSON-ключа                                  |
| `CHROME_SERVICE_ACCOUNT_PRIVATE_KEY`  | `private_key` из JSON-ключа                                   |

Без секретов workflow всё равно соберёт и протестирует выпуск и приложит архив к GitHub Release, просто не отправит его в стор.
Если предыдущая версия ещё на проверке, отправка новой завершится ошибкой — это видно в Actions, следующий запуск её повторит.

## Защита от удаления (Windows)

Любое расширение можно выключить на `chrome://extensions`. Закрепить его может только администратор компьютера с помощью политик браузера.
Это делает [`scripts/windows/install-policies.ps1`](scripts/windows/install-policies.ps1) для Chrome, Edge и Brave:

- принудительно устанавливает Block Haram из Chrome Web Store: кнопки «Выключить» и «Удалить» пропадают;
- отключает инкогнито / InPrivate, гостевой режим и добавление профилей (там расширение не работало бы);
- в Brave отключает окна Tor;
- с ключом `-FamilyDns` ставит на все активные сетевые адаптеры семейный DNS Cloudflare (`1.1.1.3`) с шифрованием DoH в Windows 11
  и отключает собственный DoH браузеров. Так фильтруются и другие браузеры и приложения.

Существующие политики не затираются, повторный запуск безопасен. Сначала посмотрите, что изменится:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows\install-policies.ps1 -ExtensionId <ID из Chrome Web Store> -FamilyDns -DryRun
```

Затем запустите ту же команду без `-DryRun` в PowerShell от имени администратора, перезапустите браузеры и проверьте `chrome://policy`.
Все изменения — это значения реестра в `HKLM\SOFTWARE\Policies\…`; администратор может их удалить.
